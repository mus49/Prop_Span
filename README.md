# Propaganda Span Detection via Biased Gibbs Sampling Refinement

This repository contains code for fine-grained propaganda span detection in news articles. The pipeline uses a locally-served LLM (Mistral-Small-3.2-24B-Instruct) via [vLLM](https://github.com/vllm-project/vllm) and operates in three sequential stages:

**Initialization → Refinement → Inference**

---

## Method Overview

For a given propaganda technique, the system iteratively improves per-article Chain-of-Thought (CoT) reasoning outputs using biased Gibbs sampling:

1. **Initialization** — generate a zero-shot CoT prediction for every article in the training set.
2. **Refinement** — for each article, sample K existing CoTs as few-shot examples and re-prompt the model. If the new prediction achieves a higher token-level F1 score, replace the stored CoT and upweight that article's sampling probability for future iterations.
3. **Inference** — use the best refined CoTs as few-shot examples when predicting spans on unseen test articles.

## Pipeline

### Step 0 — Start the vLLM Server

All three steps require a running vLLM server. Start it once and leave it running throughout the pipeline:

```bash
vllm serve models/Mistral-Small-3.2-24B-Instruct-2506 \
  --tokenizer_mode mistral \
  --config_format mistral \
  --load_format mistral \
  --tensor-parallel-size 1 \
  --gpu-memory-utilization 0.8 \
  --max-model-len 50000 \
  --max-num-seqs 6 \
  --enable-chunked-prefill \
  --port 8001
```

Adjust `--tensor-parallel-size` to match your number of GPUs.

---

### Step 1 — Initialization (Zero-Shot)

Generates a zero-shot CoT prediction for every article in the training set. The output CSV is required by Step 2.

```bash
python initialization.py \
    --tech-num 7 \
    --mapping-csv label_to_technique_mapping.csv \
    --base-url http://localhost:8001/v1 \
    --system-prompt-path models/Mistral-Small-3.2-24B-Instruct-2506/SYSTEM_PROMPT.txt
```

Key arguments:

| Argument | Default | Description |
|---|---|---|
| `--tech-num` | required | Technique number, e.g. `7` or `T07` |
| `--technique` | from CSV | Override technique name directly |
| `--mapping-csv` | `label_to_technique_mapping.csv` | Maps technique IDs to names |
| `--train-csv` | auto | Path to `Train_T{N}.csv` |
| `--out-csv` | auto | Output path for the initialization CSV |
| `--temp` | `0.15` | Sampling temperature |
| `--max-tokens` | `5000` | Max completion tokens |
| `--sleep` | `0.0` | Seconds to sleep between LLM calls |
| `--start` / `--end` | `0` / all | Index range (for resuming partial runs) |

Output: `Initialization/T{tech_num}_init_ZS.csv` with columns `gt`, `pred`, `full_article`, `CoT`, `precision`, `recall`, `f1`, `recipe`.

---

### Step 2 — Refinement

Iteratively refines each article's CoT using dynamically-weighted few-shot sampling. Set `tech_num` and `technique` at the top of the script, then run:

```bash
python i_bias_refinement.py
```

Key parameters (edit at the top of the script):

| Parameter | Default | Description |
|---|---|---|
| `tech_num` | `""` | Technique number string, e.g. `"7"` |
| `technique` | `""` | Technique name used in prompts |
| `NUM_ITERATIONS` | `25` | Gibbs sampling passes over the full dataset |
| `K` | `1` | Few-shot examples per prompt |
| `BIAS_INCREMENT` | `0.02` | Probability boost applied on F1 improvement |
| `BIAS_MAX` | `0.1` | Maximum per-article sampling probability cap |
| `TEMP` | `0.15` | Sampling temperature |

Path variables to update:

```python
openai_api_base    = "http://localhost:8001/v1"
SYSTEM_PROMPT_PATH = "models/Mistral-Small-3.2-24B-Instruct-2506/SYSTEM_PROMPT.txt"
path_df            = f"Formatted_Data/Train/Train_T{tech_num}.csv"
path_output_df     = f"Initialization/T{tech_num}_init_ZS.csv"
```

Outputs saved after each iteration to `cases/i_bias/`:
- `T{tech_num}_log_iter_{N}.csv` — per-article per-iteration log
- `T{tech_num}_finalized_iter_{N}.csv` — final CoTs and F1 scores

---

### Step 3 — Inference

Uses the refined CoTs from the final refinement iteration as few-shot examples to predict spans on the test set. Runs all techniques in parallel.

```bash
python inference.py
```

Key configuration (edit at the top of the script):

```python
TECH_IDS = [1, 2, 3, ...]   # Technique numbers to run
R_VALUES = [1, 2, 3, 4, 5]  # Number of few-shot examples to evaluate
MAX_PARALLEL_TECHNIQUES = 6  # Parallel workers (or set via env var)
```

Path variables to update:

```python
path_rf     = f"cases/i_bias/T{tech_num}_finalized_iter_25.csv"
path_df     = f"Formatted_Data/Test/Test_T{tech_num}.csv"
output_path = f"i_bias/R={R}/T{tech_num}_inference.csv"
```

You can also control parallelism via an environment variable:

```bash
MAX_PARALLEL_TECHNIQUES=4 python inference.py
```

Output CSVs contain: `article_id`, `article`, `gt_spans`, `cot`, `pred`, `F1`, `precision`, `recall`, and per-step timing breakdowns.

---

## Evaluation Metric

Spans are scored with a **token-level F1** based on Longest Common Substring (LCS) matching, computed after lowercasing and stopword removal. This tolerates minor surface-form mismatches between predicted and ground-truth spans without requiring exact string overlap.

---

## Refinement Output Schema

Each `T{tech_num}_finalized_iter_{N}.csv` contains:

| Column | Description |
|---|---|
| `article_id` | Row index of the article |
| `article` | Full article text |
| `gt_spans` | Ground-truth propaganda spans (JSON list) |
| `final_cot` | Final model output with `<CoT>` and `<span>` tags |
| `final_pred` | Extracted predicted spans (JSON list) |
| `final_f1` / `final_pre` / `final_rec` | Token-level scores |
| `updated` | Whether the CoT improved at any iteration |
| `update_history` | JSON list of `{"iter": N, "S": [indices]}` recording when and which examples triggered updates |
